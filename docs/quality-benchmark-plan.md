# 번역 품질 벤치마크 계획

## 목적

이 프로젝트에서 가장 중요한 제품 가치는 UI나 배포 형태보다 번역 결과의 품질이다.
웹 또는 앱 개발을 본격화하기 전에 반복 가능한 테스트 데이터와 평가 기준을 구축하여 다음 질문에 답한다.

- 전체 페이지를 Vision LLM에 입력하는 방식이 충분한 품질을 제공하는가?
- 페이지 단위, 여러 페이지 문맥 포함, 영역 재시도 방식 중 무엇이 가장 좋은가?
- 모델과 프롬프트 변경이 정확도, 자연스러움, 비용에 어떤 영향을 주는가?
- 실제 사용자가 만화를 계속 읽을 수 있을 정도로 결과가 일관적인가?

## 착수 시 원칙

이 문서는 향후 품질 검증 작업에 착수할 때 적용할 계획이다.
현재 단계에서는 테스트 이미지나 평가 코드를 추가하지 않는다.

1. 테스트용 원본 이미지는 저장소에 커밋하지 않는다.
2. 로컬 테스트 데이터는 이미 `.gitignore`에 등록된 `data/` 아래에서 관리한다.
3. 코드와 함께 공유 가능한 것은 스키마, 평가 기준, 합성 샘플 및 사용 허가가 명확한 자료로 제한한다.
4. 실제 상업 만화 이미지는 공개 저장소나 배포 결과물에 포함하지 않는다.
5. 모델, 프롬프트 및 파이프라인 변경은 동일한 골든 세트로 반복 평가한다.

## 제안 디렉터리 구조

```text
data/                              # Git 추적 제외
└── benchmark/
    ├── manifest.local.json
    ├── golden/
    │   └── sample-001/
    │       ├── source.jpg
    │       ├── expected.json
    │       ├── notes.md
    │       └── results/
    │           └── <experiment-id>.json
    └── incoming/                  # 아직 검수하지 않은 후보 이미지

benchmark/                         # Git 추적 가능
├── schemas/
│   ├── expected.schema.json
│   └── result.schema.json
├── prompts/
├── evaluations/
└── README.md
```

`data/`는 현재 저장소의 `.gitignore`에 이미 포함되어 있다. 착수 시 필요하면 이미지 확장자나 별도의 로컬 데이터 경로를 추가로 제외한다.

## 최초 골든 세트

처음부터 큰 데이터셋을 만들지 않고 대표적인 10페이지로 시작한다.

- 일반적인 대화 페이지 3장
- 세로쓰기, 작은 글씨, 복잡한 배경을 포함한 페이지 4장
- 효과음, 긴 대사 또는 여러 화자가 포함된 어려운 페이지 3장
- 최소 3장은 동일 장면의 연속 페이지로 구성
- 각 페이지에 사람이 검수한 기준 번역과 특이사항 기록

품질 차이를 안정적으로 구분하기 어려울 때 30페이지 수준으로 확장한다.

## 샘플 메타데이터

각 샘플에는 최소한 다음 정보를 기록한다.

```json
{
  "id": "sample-001",
  "sourceLanguage": "ja",
  "targetLanguage": "ko",
  "difficulty": "medium",
  "features": ["vertical-text", "multiple-speakers"],
  "sourceType": "licensed",
  "usageScope": "internal-evaluation",
  "dialogues": [
    {
      "order": 1,
      "type": "speech",
      "speaker": "character-a",
      "original": "まさかお前が来るとはな",
      "reference": "설마 네가 올 줄은 몰랐군.",
      "tone": "낮잡아 말하는 반말"
    }
  ]
}
```

`sourceType`과 `usageScope`를 필수로 두어 이미지의 출처와 허용 범위를 추적한다.

## 평가 항목

각 실험은 다음 항목을 분리하여 평가한다.

| 항목 | 설명 |
|---|---|
| 대사 검출 | 번역 대상 텍스트를 누락하거나 불필요한 텍스트를 포함하지 않았는가 |
| 원문 인식 | 일본어 원문을 정확하게 읽었는가 |
| 읽기 순서 | 말풍선과 대화 순서를 올바르게 판단했는가 |
| 의미 정확성 | 원문의 핵심 의미를 보존했는가 |
| 한국어 자연스러움 | 번역투가 적고 자연스럽게 읽히는가 |
| 말투 일관성 | 존댓말, 반말 및 캐릭터 말투가 유지되는가 |
| 고유명사 일관성 | 이름과 용어가 페이지 사이에서 동일한가 |
| 위치 정확도 | 번역문이 올바른 말풍선 또는 영역에 연결되는가 |
| 시각적 품질 | 글자 크기와 배치가 읽기 쉽고 원화를 과도하게 가리지 않는가 |

대사 누락, 의미 반전, 화자 반전 및 존재하지 않는 대사 생성은 별도의 치명적 오류로 집계한다.

## 우선 비교할 실험

1. 한 페이지 전체를 한 번에 입력
2. 현재 페이지와 이전 페이지의 번역 문맥을 함께 입력
3. 여러 연속 페이지를 한 요청에 입력
4. 전체 페이지 처리 후 불확실한 영역만 잘라 재시도
5. 작품별 캐릭터, 고유명사 및 말투 컨텍스트 포함
6. 모델과 이미지 상세도에 따른 품질·지연시간·비용 비교

각 실행 결과에는 모델, 프롬프트 버전, 입력 이미지 설정, 처리 시간, 예상 비용 및 평가 점수를 함께 저장한다.

## 사용자 업로드 데이터의 향후 활용

서비스 출시 후 사용자 업로드를 품질 개선에 활용할 수 있지만, 번역 처리를 위한 업로드와 테스트·검증 목적의 재사용을 구분한다.

- 품질 개선 참여는 별도의 선택 동의로 제공한다.
- 선택 항목은 기본적으로 비활성화하며, 거부해도 번역 기능에 불이익이 없어야 한다.
- 동의 화면에 이용 목적, 데이터 항목, 보유기간, 철회 및 삭제 방법을 명시한다.
- 동의하지 않은 원본 이미지는 번역 처리 후 정해진 기간 안에 삭제한다.
- 사용자 업로드 원본은 Git 저장소에 커밋하지 않고 삭제 가능한 객체 저장소에 보관한다.
- 사용자의 동의가 이미지 저작권까지 보장하지 않으므로 내부 활용 범위와 데이터 선정 기준을 별도로 검토한다.
- 테스트 세트 편입 전 개인정보, 민감정보 및 불필요한 메타데이터 포함 여부를 검수한다.

## 공개 및 배포 원칙

향후 프로젝트를 공개하거나 배포할 때는 다음 자료만 포함한다.

- 직접 제작하거나 사용 허가가 명확한 샘플
- 합성 또는 생성형 테스트 이미지
- 데이터 스키마와 평가 도구
- 프롬프트와 비식별화된 평가 통계
- 원본을 재현할 수 없는 오류 유형 및 품질 리포트

비공개 로컬 데이터가 빌드 결과물, 테스트 아티팩트 또는 배포 패키지에 포함되지 않는지 배포 전에 자동 검사한다.
